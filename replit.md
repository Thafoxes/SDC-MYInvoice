# NudgeWise on Replit

## Scope and constraints

- Keep the existing Vue 3/Vite frontend and Node 24 backend on branch `replit-deploy`. Do not switch to or commit on `main`.
- Hosting setup must not change business rules in `src/lib/`, Telegram/receipt logic in `server/integrations.cjs`, or existing tests.
- Do not migrate the SQLite database or publish without the user's explicit request. The user will publish manually.
- This remains a synthetic-data, single-seller demo, not production payment verification or multi-user authentication.

## Run

Use the **Run** button (`Start application` workflow), or `npm run start`.
This builds the Vue frontend and server logic, then starts `server/app.cjs`.
One HTTP server serves `dist/`, SPA routes, and `/api`.

- Node **24+** is required for `node:sqlite`; the configured module is Node 24.
- Python **3.12** and the packages in `server/requirements.txt` are required for OCR.
- Replit's package installer mirrors those Python requirements in `pyproject.toml` and `uv.lock`. Keep these manifests aligned with the existing requirements file.
- Replit installs Python dependencies in `.pythonlibs/`. `DOCLING_PYTHON=.pythonlibs/bin/python` points the unchanged OCR integration at that interpreter.
- `main.py` is unused scaffolding generated by Replit's Python package installer, not an application entry point.
- Replit sets `PORT=5000`; the server then listens on `0.0.0.0`. Without `PORT`, the existing local default is `127.0.0.1:8787`.
- Public startup (`PORT` set) refuses to run without a nonempty `DEMO_ACCESS_KEY`. API handling also fails closed in this configuration. Only loopback mode without `PORT` allows an unset key.
- Do not run a second copy of the same Telegram polling bot while the preview or deployment is running. Stop the workspace workflow when publishing to avoid competing pollers.

## Secrets and origins

Existing Replit Secrets: `DEMO_ACCESS_KEY`, `TELEGRAM_BOT_TOKEN`, `OLLAMA_API_KEY`, `OLLAMA_MODEL`, `TELEGRAM_BUSINESS_ID`, `RECEIPT_BENEFICIARY`, and the non-sensitive frontend feature flag `VITE_TELEGRAM_ENABLED`.
Never put credentials in source, frontend bundles, or any `VITE_*` variable. `VITE_TELEGRAM_ENABLED` must be the literal `true` to use the API-backed UI, and changes require a frontend rebuild.

When `DEMO_ACCESS_KEY` is set:

- API data, commands, and receipt downloads require `X-Demo-Key` or the signed session cookie.
- `GET /api/access` only reports whether access is required/authenticated; it exposes no invoice data.
- `POST /api/access` checks the submitted passcode and sets a 12-hour HttpOnly cookie. HTTPS uses Secure, SameSite=None, and Partitioned so sessions work inside the preview iframe; loopback HTTP uses SameSite=Strict. API origin checks reject foreign-origin requests.
- The frontend shows **Demo access** before mounting the main application. It never stores the passcode in browser storage.
- Invalid login attempts are rate-limited in a bounded process-wide window. This shared demo key is not individual user authentication.

Same-origin HTTPS requests are allowed automatically. For additional permitted origins, set `FRONTEND_ORIGIN` to exact origins, optionally comma-separated, with no trailing slash, for example `https://first.example,https://second.example`. This is an origin check, not a cross-origin API/CORS feature.

## Publishing configuration (not yet published)

- Target: **Reserved VM** (`vm`), not Autoscale, because Telegram long polling and the 30-second monitor need a continuously running process.
- Build: `npm ci && UV_PROJECT_ENVIRONMENT=.pythonlibs uv sync --frozen`
- Run: `npm run start`
- HTTP port: **5000**
- Python and Node dependencies are installed during the build rather than relying on workspace dependency directories.

Before publishing manually:

1. Open Publishing settings and confirm Reserved VM, the commands above, and the port mapping.
2. Confirm all listed secrets and `PORT=5000` / `DOCLING_PYTHON=.pythonlibs/bin/python` are present in the deployment environment. `VITE_TELEGRAM_ENABLED=true` must be available when the frontend builds.
3. Choose VM memory appropriate for Docling/PyTorch OCR; it is considerably heavier than the web frontend. Model files may download on the first OCR run, so test a synthetic receipt before a live demonstration.
4. Stop any other instance polling the same Telegram bot, including this workspace workflow.
5. Publish yourself. No publishing was performed during setup.

## SQLite persistence: important

Authoritative API data stays in `.local-data/demo.sqlite`; downloaded receipts are in `.local-data/`. The database was not migrated.

- A restart of only the Node process **on the same filesystem** reopens the existing SQLite file.
- A Reserved VM is always-on compute, **not a durable-volume guarantee**. Do not rely on these files surviving deployment instance replacement/restart.
- **Publish/republish/redeploy can reset the deployment filesystem and lose the SQLite database and receipt files.** Workspace SQLite data is not copied into deployments.
- This setup intentionally excludes `.local-data/` from source/deployment inputs. Use synthetic disposable data and do not treat it as durable record storage.
- A durable-storage/backup strategy requires a separate user-approved change; no database migration or backup service was introduced.

References: https://docs.replit.com/build/troubleshooting and https://docs.replit.com/cloud-services/deployments/reserved-vm-deployments

## Verification

Existing checks (unchanged tests):

```sh
npm run test:logic
env -u DEMO_ACCESS_KEY -u PORT npm run test:telegram
npm run build
```

The Telegram suite assumes an unprotected loopback test server, so deployment-only access/port settings are removed **only from that test process**, not from the running application.

Verified: 13 logic tests, 47 Telegram/AI tests, production build, Python 3.12 Docling and ONNX Runtime imports, and the running preview passcode screen.
An isolated backend with a separate temporary database and synthetic access key was used to verify browser login, Dashboard, Action Center, authenticated `/api/state`, session-expiry gating, header/cookie protection, secure-cookie flags, origin allowlists, SPA serving, and private-file isolation. The running preview's unauthenticated `/api/state` returns 401.
No live Telegram messages were sent and no real receipt/Ollama inference was performed as part of verification.
